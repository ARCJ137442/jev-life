# UI 规格（T14–T15 评审稿）

这份文档汇总**用户在多轮对话里给过的全部 UI 规格**，供 T14 开工前逐条确认。
分区的判据与「为什么」见 `DESIGN.md` 第六、七、十节。

**`★` 标记的是本轮实测新出的、会改变原规格的结论** —— 那几条最需要你重新过目。

---

## 一、范围与模式

| 模式 | v1 做吗 | 说明 |
|---|---|---|
| **Jev vs Jev（双人对弈，全 AI）** | ✅ | 生之执与死之执各一个后端，是跨模型对照的载体 |
| **纯生执单人** | ✅ | 无对手，只看累计净增长 |
| 人手动落子 | ❌ | 单人/双人的交互设计不同，M1 不做 |

「**AI 也是玩家**」——所以下文的「玩家」一律指**行动方**（不管是 AI 还是人），
界面文案里不出现「玩家」这个含混词，直接用「生之执 / 死之执」。

## 三、配色、棋盘与动画

### 主题色：青 `#22d3ee`（用户定）

**为什么只能在这一带选** —— 四个色相已被**内容**占用：

| 色彩 | 被谁占用 |
|---|---|
| **白** | 活细胞 |
| **绿** | 生之执（落子发光选框、生死态势图界限、置信度面积、决策热力图） |
| **红** | 死之执（同上） |
| **黄** | 中段 / 交集（生死态势图中线渐变、置信度面积图的交集区） |

剩下的安全区只有青 / 蓝 / 紫。**选青**：与绿差 60°、与红差 180°，色相距离够；
冷调、退让，不抢绿红的角色语义。

### ★ 面板底色必须跟着从暖转冷

`jev-2048` 的面板是**刻意偏暖**的 —— 不只是强调色是橙，底色也带棕调：

```
--bg:#0a0a0a;  --panel:#121110;  --panel-2:#1a1816;   ← 偏暖，为呼应橙色
--accent:#f59e0b;  --accent-2:#fbbf24;  --red:#f87171
```

**换主题色不只是换一个变量。** 面板底色不跟着换冷暖，就会出现
「**冷色强调 + 暖色底**」的脏感。所以底色与面板要改成**偏冷或纯中性**的一组 ——
具体值留给实现时对着实物调。

### 棋盘与动画

**配色**：深色底 + **白色活细胞**（生命游戏的常规配色）。

| 动画 | 触发 | 表现 |
|---|---|---|
| **落子** | 任一行动方翻转一格 | 格子 `0 → 1` 缩放，**ease-out（快起慢收）**；**外加发光选框淡出** —— 生之执 **绿**、死之执 **红** |
| **迭代** | 演化一代 | 状态改变的格子缩放淡入淡出，**不带发光选框** |
| **粒子** | 落子处 | 复用 2048 的 `burst` 骨架 |

### ★ 时序：以「选框」为基准的四段比例（用户定，2026-09-21）

**缩放 : 粒子 : 选框 : 落子→演化的间隔 = 1 : 1 : 2 : 2**

以选框时长（默认 **1.0s**）为基准单位，一轮展开是：

| 时段 | 从 | 到 | 发生什么 |
|---|---|---|---|
| **落子相** | 0 | **1.0s** | 方块缩放（前 0.5s）+ 粒子（前 0.5s）；**发光选框铺满整段**，从出现到淡出 |
| **演化相** | **1.0s** | 1.5s | 演化一代：方块缩放 + 粒子（**0.5s，没有选框**） |
| **空余** | 1.5s | **2.0s** | 静止。留给眼睛把「刚才发生了什么」看完 |
| | | | **一轮合计 2.0s = 2 × 选框时长** |

**要点在于「谁是基准」**：`flipMs` 这个可调参数是**选框的时长**，也是**落子到演化的间隔**；
缩放与粒子只占它的**一半**。早先的实现让三者都跟着 `flipMs` 走（缩放/粒子/选框同长），
那是错的 —— 用户看实物后指出：**选框要比缩放留得久**（它要回答「这是谁落的子」，
而缩放只是「这里刚变过」的反馈），两者同长就分不出主次。

**「演化相隔 1.0s」与「空余 0.5s」是两件事**：前者是「落子相演完才轮到演化」，
后者是演化演完之后到下一回合之间的留白。

**发光选框在 v1 全程可见**（因为 AI 也是玩家）——所以这个效果在 v1 就能被验证好坏，不用等手动模式。

### 复用与不复用

| 复用 | 不复用 |
|---|---|
| `Map<id, Visual>` 目标值模型（视觉层自带 `x/y/scale/alpha` 与目标值） | `SCALE` 橙色阶 |
| 指数逼近补间（按**实际帧间隔**归一化，写法是对的） | `GLYPH` 方向箭头 |
| 懒启动 rAF、DPR 夹 2.5、`GUTTER_K` 几何（pad 与 gap 必须相等） | 按位数分档的数字字号 |

## 四、侧栏：计分板与三张图

### 记分板（用户定）

从左到右：**`ALIVE` | `RATIO` | `TURN` | `A.MAX` | `A.MIN`**

| 列 | 含义 |
|---|---|
| `ALIVE` | 当前活细胞**数量** |
| `RATIO` | 活细胞**占比（百分比）** |
| `TURN` | 当前回合 |
| `A.MAX` | **本局**活细胞数的**最大**值 |
| `A.MIN` | **本局**活细胞数的**最小**值 |

每一列**不超过 5 个字母**，这样窄屏也不会折行。
`A.` 前缀表示「整局范围」（对应 2048 那套里的 `B.Max` 位置）。

> 替换掉 2048 的 `Score / Best / Turn / Max / B.Max` —— 生命棋里「分数」不是一个独立概念，
> 活细胞数与占比才是。

### 排布（从上到下）

```
┌─ 卡片一 ─────────────────────────┐
│  ALIVE  RATIO  TURN  A.MAX  A.MIN │
│  ──────────────────────────────── │
│  生死态势图（②）                    │   ← 与计分板**融合在同一张卡片**
├──────────────────────────────────┤
│  决策热力图（③）                    │
│  ── ── ── ── ── ── ── ── ── ── ── │   ← ③ 与 ① **同处一卡**
│  置信度面积图（①）                  │
└──────────────────────────────────┘
```

两个判断的依据：

1. **② 与计分板融合**：两者说的都是**游戏本身的客观状态** —— 计分板是本回合的瞬时值，
   态势图是它的时间序列，**同一件事的两个视角**。分成两张卡反而会让人以为它们无关。
2. **③ 与 ① 同处一卡**：两者说的都是**模型** —— ③ 是当回合的决策分布，
   ① 是它的历史。**同一件事的「此刻」与「历来」**，与卡片一那条判据是同一个道理。

### 先分清三张图各画的是什么

**① 与 ③ 都是「模型」的图，② 是「游戏」的图。** ① 与 ③ 的区别在时间维度：

| | ① 置信度 | ② 生死态势 | ③ 决策概率 |
|---|---|---|---|
| **画的是谁** | 模型 | **游戏** | 模型 |
| **时间维度** | 时间序列（历史每一手） | 时间序列（历史每回合） | **当回合** |
| **2048 里长什么样** | 一条带状面积 | 无 | **四根横条**（↑↓←→） |
| 回答什么问题 | 模型这些年**有多确信** | **谁占优、离赢多远** | 这一手，**每个候选各多少概率** |

### ① Jev 决策的历史置信度

沿用 2048 的带状面积图（top / bottom / median 三标量）：**带宽 = 这一手概率分布有多分散，中线 = 中值**。
它是一条**时间序列**，横轴是回合。

**双人对弈模式下两组合并进同一张图**：

- 生之执的面积 **绿**，死之执的 **红**
- 两块面积的**交集区域渲染成黄色**
- 中值折线**各跟随各自玩家的颜色**

### ★ 胜负线要可配置 + 态势图标签用整数百分比（用户定，2026-09-21）

**1 · 胜负线成为「游戏」抽屉里可配置的项**

用户原话：*「至少胜负线需要成为一个可在「游戏」中配置的项」*。

**⚠ 这条推翻了 T14 的一个决定**（「胜负线只读，只开放回合上限」），当时的理由是
「预设标着 `calibrated: false`，做成滑块会**暗示它们已经标定过**」。

那个顾虑仍然成立，但**解法不是藏起来，而是标注** —— 藏起来并不能让它变准，
只会让人以为它不可调。所以：控件可拖，旁边明说「这些值是占位、未经跑分标定」。

`lifeWinRatio` / `deathWinRatio` / `lifeStreak` / `deathStreak` 全部开放，
放在**「游戏」抽屉**（按 `DESIGN.md` 第七节，它们是**对局级**的博弈定义），
且**必须进 `state`**。

**2 · 态势图的标签改成整数百分比**

现在画的是 `0.60` / `0.50` / `0.05`。改成 **`60%` / `50%` / `5%`** ——
整数百分比，不要 `5.0%`，也不要 `0.05`。纵轴的 `1.0` / `0.0` 同理改 `100%` / `0%`。

用户原话：*「两条线、标尺都呈现为整数百分比为好，避免「0.」的冗余」*。

**3 · 默认值本身也下调了：`lifeWinRatio` 0.6 → 0.30**

| 棋盘 | 新默认 | 含义 |
|---|---|---|
| 8×8 / 16×16 | **0.30** | 8×8 上 = 19 格（净增 10） |
| **4×4** | **0.50** | 单独取，见下 |

0.6 从来没标定过，它是设计文档里的示例数字。而它意味着生之执要把活细胞从开局的
9 格（14.1%）堆到 **38 格**（净增 29），而死之执只要压到 3 格（5%）就赢 ——
**两边难度差得太远，不是一条对称的胜负线。**

> ★ **4×4 为什么单独取 0.5**：改完之后 `presets` 那条「每个开局至少能撑 20 代」
> 当场变红 —— 0.30 在 4×4 上只等于「≥ 5 格」，而预设开局 beacon / toad 本来就是
> 6 格（37.5%），**一开局就已经越过胜负线**，三代后生之执直接获胜。
>
> 根因是**小棋盘的分辨率粗**（4×4 上一格 = 6.25%）。所以这一档的阈值必须**更高**。
>
> **这是「自由尺寸下必须标注『该尺寸的参数未标定』」那条规格的活例子** ——
> 用户填 5×5、7×11 时，预设那套阈值落下去会是什么效果，没人知道。
> 写提示时用这个例子，比空说一句「未标定」具体得多。

### ★ 首页布局调整（用户实测后反馈，2026-09-21）

**三条，都是看了实物才发现的。**

**1 · 生死态势图的填充要「以折线为界」，不是以 0.5 为界**

原实现填的是「折线与 0.5 中线之间」的区域。用户要的是**整幅填满，折线就是那条国界线**。
**方向已确认**（我第一版写反了，用户看过预览后选定）：

```
活细胞占比
1.0 ┤▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  红 = 死细胞份额
    │▓▓▓▓▓▓▓▓▓╱╲▓▓▓▓▓▓▓
0.5 ┼░░░░░░╱──╲░░░░░░░  0.5 中线（背景参照，不再决定填色）
    │░░░░╱░░░░░░╲░░░░░
0.0 ┤░░░░░░░░░░░░░░░░░░  绿 = 活细胞份额
    └──────────────────→ 回合
```

- **折线以下填绿**（高度 = 活细胞占比）、**以上填红**（= 死细胞份额）
- 于是**占比越高，绿越大** —— 绿看着变大就是生之执在赢，与直觉一致
- 0.5 参考中线保留，但降级为背景参照
- ⚠ 折线会在 0.5 上下**来回穿插**，填色要**分段**处理

用户的原话是：*「这样子是呈现出的两个区域之间推拉，像国界线一样」* ——
固定 50% 为界的画法只在曲线穿过中线时才变色，**推拉的动感全丢了**。

> ⚠ **这处我读反过一次。** 用户原话是「边界上边是绿色区域」，而纵轴下 0 上 1、
> 线上方是 `1 − 占比` ——「上绿」与「上方是死细胞份额」对不上。**把它做成预览图
> 让用户挑，才定下来是「下绿上红」。** 文字描述的方位与图形语义容易相反，
> 这类规格要在动手前用图确认一次。

**2 · 生死态势图的高度压到目前的一半，上下内边距缩到与左右相同**

理由是**侧栏空间稀缺** —— 它占的高度要从别处挤出来。

**3 · 「置信度追踪」并到「本回合决策」的热力图右侧**

卡片二合一：**热力图在左、置信度面积图在右**。削掉一些宽度，换回一整张卡片的高度，
**腾出来的高度留给文本说明**（决策理由、日志摘要那类要读的东西）。

> 先前把三张图纵向堆叠是「先按堆叠做，窄了再折叠」的临时决定（见 `ui-spec.md` 第九节）。
> 实测下来是**高度不够**，所以这条把它收敛成了两卡。

### ② ★ 生死态势图（正式定名）

放在 ① 的**下方**（它是游戏的客观状态，不是模型的输出）。

纵轴是活细胞占比 0~1（**下 0 上 1**）。四条水平元素：

| 元素 | 含义 | 样式 |
|---|---|---|
| **生之执界限** | `lifeWinRatio`（默认 0.6） | **绿**色虚线 |
| 0.5 参考中线 | 二分线 | 中性虚线 |
| **死之执界限** | `deathWinRatio`（默认 0.05） | **红**色虚线 |
| **实际值折线** | 每回合的活细胞占比 | 描边颜色**随高度渐变**：低处红 → 中段黄 → 高处绿 |

- 实际值折线与 0.5 中线围成的面积就是「优势面积」——折线在 0.5 以上时填**绿**，以下填**红**
- **越界时在线头画一个圆点**，颜色与该方界限匹配，圆内显示**已连续越界多少轮**
- **单人模式原封不动保留**

> 配色口径：**上生绿、下死红**（按图表默认的下 0 上 1）。

### ③ 决策概率图 —— **就是 2048 那张，换个画法**

**它的身份是「呈现模型本回合的决策分布」。** 2048 里候选只有四个方向，所以画成四根横条。

**生命棋里改成一张与棋盘同形的热力图**，放在侧栏（即 2048 那张条形图原来的位置）：

| 属性 | 做法 |
|---|---|
| **形状** | **与棋盘同形**的 N×N 网格，**不叠在真棋盘上** |
| **底色调** | **按角色分**：生之执**绿系**、死之执**红系** |
| **概率大小** | 用**亮度 / 不透明度**表达 |

**它替换掉 2048 的「↑↓←→ 各决策概率」条形图，不是新增一张。**

**「不叠在真棋盘上」是刻意的**：真棋盘只表达「当前局面」这一件事，
让概率去染它的格子，两件事就糊在一起了；而两张棋盘并排又容易看混。
独立一张小图，位置明确、互不干扰。

**双人模式也只要一张。** 而且这里有一条很干净的性质：

> 棋盘上每一格，**恰好属于一个角色的候选集** —— 死格是生之执的候选，活格是死之执的候选。
> 所以两个角色把 N² 个格子**完整瓜分**，热力图上**每一格都有值、没有空隙、也不重叠**。

（这与「同时决策无需冲突消解」是同源的性质。）

> ⚠ **别与 ① 混了**：① 是时间序列（历史上每一手有多集中），③ 是当回合的空间分布。

### ★ 三条会改变原规格的实测结论

1. **思维链默认关**。实测：两个后端（免费 agnes / 付费 deepseek）都从 0–63% 升到 **100%**，
   快 5–40 倍，推理 token 归零。而且关掉它**从结构上消灭了「推理吃光预算」这个失败模式** ——
   那是观察到的**唯一**失败原因。

2. **思考强度实测有害，不只是无用**。每档 3 次、思维链开：

   | 档位 | 成功率 |
   |---|---|
   | **无 `none`** | **3/3** |
   | **默认（留空）** | **3/3** |
   | 低 / 中 / 高 / 最强 | **0–1/3** |

   四个显式档位**全部劣于不设**，而且不是单调的（规律是「只要设了就变差」）。
   **建议：保留控件但默认留空，并把这条实测写进 UI 提示**，让人知情地选。
   （**只有一个后端的数据**，别家可能不同——所以不建议直接删掉控件。）

3. **UI 的枚举不能直接下发**。该后端只接受 `none | low | medium | high | max`，
   **不收 `xhigh`**——直接发会 **400 把整个请求打掉**。
   所以 broker 必须持有**后端能力表**：支持就发，不支持就**不发**（留空用默认），
   并在 UI 标注「该后端不支持，已降级为默认」。

### 两个思考控件的耦合

`是否允许思考` 与 `思考强度` 里的 `none` 语义重叠。建议：
前者选「否」时强度**置灰显示 `none`**；强度选 `none` 时前者自动显示「否」。
两者最终归一到同一个下发字段（或按后端能力分别落到 `reasoning_effort` 与
`chat_template_kwargs.enable_thinking`）。

### ★ 棋盘尺寸可自定义（用户定，2026-09-21 追加）

**长与宽分别可设，各自 2~16。**

这与「预设只用正方形、边长取 2 的幂」**不冲突，而是两层**：

| 层 | 尺寸 | 为什么 |
|---|---|---|
| **预设** | 4 / 8 / 16（正方形） | 它们带**成套的标定参数**（开局库、回合上限、阈值）。换尺寸就得整套重标 |
| **自定义** | 长宽各自 2~16，可非方 | 给"我想试试这个尺寸"用。**参数由用户自己负责**，界面要标明这一点 |

⚠ 两条必须一起做，否则用户会以为自定义尺寸下那套预设参数还成立：

1. 预设按钮与自由输入**并列**，后者要能填长、填宽
2. 自由尺寸下，界面须显示「**该尺寸的参数未标定**」——预设的回合上限/阈值是
   为 4/8/16 调的，套到 7×11 上没有任何依据（这正是 `calibrated: false` 那条的延伸）

**已知退化**：`MIN_SIZE` 原本是 4，理由是**环绕拓扑下 2~3 的尺寸语义诡异**
（`rows = 2` 时 `r-1` 与 `r+1` 是同一行，邻居被重复计数）。
放宽到 2 之后，**有界拓扑下 2×2 是合法的**（一个方块就是静物），
但 **torus + 极小尺寸的组合仍然没有意义** —— 界面在这种组合下应当提示，
而不是默默算出一个别人看不懂的结果。

### ★ 开局可以手绘（用户定，2026-09-21 追加）

**「开始对弈」之前允许手动布置开局，开始之后才禁止手动干预。**

理由（用户原话）：*「这样子可以让玩家自定义绘制开局，不仅仅是预设，就有很大可玩性」*。

- 未开始对弈时：**点格子即翻转**，随意画出任意局面
- 点「开始对弈」后：棋盘锁定，只有行动方的 AI 落子能改它

**⚠ 开局前的点击只触发方块的缩放动画，没有粒子、也没有发光选框**（用户定）。

理由是两者的语义不同：

| | 开局前的点击 | 对局中的落子 |
|---|---|---|
| 是什么 | **编辑**（在摆棋盘） | **行动**（一个角色的决策） |
| 动画 | 只有格子 `0↔1` 的缩放 | 缩放 + **发光选框**（生绿死红）+ **粒子** |

粒子与发光选框在规格里是**「某个角色落子」的视觉标记** —— 开局前还没有角色，
把它们借过来会让人以为那是某一方下的子。**缩放本身就是「这一格刚被改过」的反馈**，够了。
- 这**不与「v1 不做人手动落子」冲突** —— 那是**对局中**的干预，
  这里是**对局前**的布置，两者的语义完全不同

**实现上几乎没有额外成本**：点击翻转的逻辑与「手动落子」是同一条路径
（点格子 → `legalCells` 检查 → `flip`），区别只在**允不允许**。
所以将来要做对局中手动落子时，这层已经在了。

**要一并处理的两件事**：
1. 手绘之后，「开局预设」的选择应当**被标记为『自定义』**，而不是继续显示某个预设名 ——
   否则界面会声称这局用的是 `block-glider`，而棋盘上是别的东西
2. 手绘的局面**允许不满足"离边缘 ≥2 格"**（那是给预设定的规矩，人手画的没有这个约束），
   但界面可以给个温和提示

### 开局选择器（用户定）

**位置：「游戏」抽屉里一个独立分区，且在「游戏本身的属性」下方。**

**顺序是有依赖的：先定棋盘尺寸，再定开局。** 开局库按尺寸分级
（4 / 8 / 16 各一套，见 `presets.ts`），所以尺寸变了可选开局就跟着变 ——
控件顺序必须体现这个依赖，否则用户会先选一个开局、再改尺寸，然后发现选的那个没了。

**要能画出形状**，不只是文字名称。`Opening.preview` 就是为此准备的 ——
用 monospace 字符网格渲染缩略图即可，不必用 canvas。**完整交互留到 M2。**

## 七、统计页面（后续）

按 **`后端 × 模型 × 调用配置`** 分组，**不是按模型分组**——同一模型开/关思维链是两个不同的东西
（100% vs 63%），混在一起算平均得到的数字谁也不代表。

| 指标 | 为什么非有不可 |
|---|---|
| **单次成功率** | 必须与「重试后的成功率」分开 |
| 重试 N 次后的成功率 | 决定配几次重试才够用 |
| 重试次数分布 | 平均值会掩盖「一半一次过、一半要五次」 |
| **限流比例（429）** | 不单列就会被算进「模型不行」 |
| **延迟的分位数**（中位 / p90）而非平均 | 实测见过 1.1 s 与 190.9 s，平均值没有意义 |
| 推理 token 占比 | 关思维链前后是 0% 与 90%+ |
| 成本 | **必须标注价目表日期** |

**可重置** —— 否则跑完一轮对照，第二轮的数据会被第一轮污染。
